REQUEST FOR PROPOSAL (RFP)
==========================
Travel Management Application on SAP Business Technology Platform

Issuing Organization : GlobalTech Industries AG
RFP Reference        : RFP-GT-2026-TM-042
Issue Date           : 2026-08-15
Submission Deadline  : 2026-09-30
Contact              : procurement-btp@globaltech-industries.example.com

------------------------------------------------------------------------
1. COMPANY BACKGROUND
------------------------------------------------------------------------
GlobalTech Industries AG is a multinational manufacturing company
headquartered in Munich, Germany, with 18,000 employees across 35
countries. The company currently operates SAP S/4HANA 2023 as its core
ERP system, uses SAP SuccessFactors for HR, and SAP Concur for expense
management. Travel booking is handled through a legacy on-premise system
that is reaching end of life in Q2 2027.

------------------------------------------------------------------------
2. PROJECT OBJECTIVE
------------------------------------------------------------------------
GlobalTech seeks a modern, cloud-native Travel Management Application
built on SAP BTP using the SAP Cloud Application Programming Model
(CAP). The application must replace the existing legacy travel system
and integrate seamlessly with S/4HANA, SuccessFactors, and Concur.

------------------------------------------------------------------------
3. FUNCTIONAL REQUIREMENTS
------------------------------------------------------------------------

3.1 Travel Request Management
    - Employees must be able to create, edit, and submit travel requests.
    - Each request must capture: trip purpose, destination(s),
      travel dates, estimated budget, cost center, and project code.
    - Multi-leg trips (e.g., Munich -> New York -> Chicago -> Munich)
      must be supported with per-leg details.
    - Draft saving and request cloning from previous trips.

3.2 Approval Workflow
    - Configurable multi-level approval chains based on cost center,
      travel budget threshold, and destination risk level.
    - Manager approval via SAP Build Work Zone and email notification.
    - Auto-approval for domestic trips below EUR 500.
    - Escalation rules when approvers do not act within 48 hours.
    - Delegation support for approvers on leave.

3.3 Booking Integration
    - Integration with at least one Global Distribution System (GDS)
      or travel booking API for flight and hotel search/booking.
    - Display of corporate-negotiated rates and preferred suppliers.
    - Seat selection, meal preference, and loyalty number capture.
    - Hotel booking with room-type preference and cancellation policy
      display.

3.4 Travel Policy Enforcement
    - Real-time policy checks during request creation:
      * Maximum per-diem rates by destination country.
      * Advance booking requirements (minimum 14 days for flights).
      * Class-of-service rules by employee grade (economy, premium
        economy, business).
      * Preferred airline and hotel chain enforcement with
        out-of-policy justification workflow.
    - Policy rules must be maintainable by HR admins without developer
      involvement.

3.5 Expense Reporting
    - Post-trip expense report creation linked to the original travel
      request.
    - Receipt upload (photo capture on mobile, drag-and-drop on
      desktop) with OCR-based auto-population of amount and vendor.
    - Per-diem calculation engine by country with half-day logic.
    - Foreign currency handling with automatic exchange rate lookup
      from S/4HANA.
    - Integration with SAP Concur for final reimbursement processing.

3.6 Dashboard and Analytics
    - Manager dashboard showing team travel spend, upcoming trips,
      and pending approvals.
    - Finance dashboard with spend-by-cost-center, spend-by-region,
      and budget-vs-actual views.
    - Travel admin dashboard with policy violation trends,
      preferred-supplier adoption rate, and average lead-time metrics.
    - All dashboards must support drill-down to individual requests.

3.7 Notifications and Communication
    - Email and in-app notifications for request status changes,
      approval reminders, booking confirmations, and itinerary updates.
    - Integration with Microsoft Teams for approval action cards.
    - Automated pre-trip reminder emails with destination-specific
      travel advisories.

------------------------------------------------------------------------
4. NON-FUNCTIONAL REQUIREMENTS
------------------------------------------------------------------------

4.1 Performance
    - Page load time under 2 seconds for 95th percentile.
    - Support for 5,000 concurrent users during peak booking periods.
    - Search results from booking APIs within 5 seconds.

4.2 Security and Compliance
    - Authentication via SAP Identity Authentication Service (IAS)
      with corporate Active Directory federation.
    - Role-based access control: Employee, Manager, Travel Admin,
      Finance, System Admin.
    - GDPR compliance for employee personal data, including the right
      to erasure.
    - Audit trail for all approval decisions and policy overrides.
    - Data encryption at rest and in transit (TLS 1.3).

4.3 Availability and Disaster Recovery
    - 99.5% uptime SLA during business hours (06:00-22:00 CET).
    - Recovery Point Objective (RPO): 1 hour.
    - Recovery Time Objective (RTO): 4 hours.
    - Multi-region deployment consideration for APAC and Americas.

4.4 Mobile Support
    - Responsive UI accessible on iOS and Android devices.
    - Offline capability for expense receipt capture.
    - Push notifications for approval tasks.

4.5 Accessibility
    - WCAG 2.1 AA compliance.
    - Screen reader compatibility for all core workflows.

------------------------------------------------------------------------
5. TECHNICAL REQUIREMENTS
------------------------------------------------------------------------

5.1 Platform and Architecture
    - SAP BTP Cloud Foundry or Kyma runtime.
    - SAP CAP (Node.js or Java runtime) for backend services.
    - SAP HANA Cloud as the primary database.
    - SAP Fiori Elements or SAPUI5 freestyle for the frontend.
    - SAP Build Work Zone, standard or advanced edition, as the
      launchpad.

5.2 Integration
    - OData V4 APIs for all service endpoints.
    - SAP S/4HANA integration: cost center, project, employee master
      data, exchange rates (via SAP BTP Destination Service and
      SAP Cloud Connector).
    - SAP SuccessFactors: organizational hierarchy and employee
      profile synchronization.
    - SAP Concur: expense submission and reimbursement status.
    - Event-driven architecture using SAP Event Mesh for cross-system
      notifications.

5.3 Extensibility
    - Extension points for customer-specific fields on travel requests.
    - Configurable approval rules without code changes.
    - Public API for third-party travel agency integration.

5.4 DevOps and Lifecycle
    - CI/CD pipeline using SAP CI/CD Service or GitHub Actions.
    - Automated unit and integration testing (minimum 80% code
      coverage for backend services).
    - Blue-green deployment strategy.
    - SAP Cloud Transport Management for promoting between dev, QA,
      and production.

------------------------------------------------------------------------
6. DATA MIGRATION
------------------------------------------------------------------------
    - Migration of approximately 120,000 historical travel requests
      (3 years) from the legacy system.
    - Data cleansing and mapping strategy must be documented.
    - Parallel run period of 4 weeks before legacy system
      decommission.
